## Summary / 总评

当前建议：**2/10，拒绝；置信度 4/5。** 决定性原因是当前稿仍把没有结果的双语主实验列为贡献，同时质量实验的归一化指标含义写错，且主要任务解释对评分、聚合方式敏感。单种子本身不是自动拒绝理由；它要求论文把贡献限定为可复核的探索性观察。预算不足可以通过缩小主张和完善现有证据审计应对，不能把计划中的重复实验计作证据。

论文围绕小型中英双语预训练的数据筛选、语言配比与训练顺序提出研究框架。已给出的英文质量扫描覆盖五种规模、两个数据条件，各训练约 20B tokens。我的独立复算确认：最终十任务原始准确率宏平均增益依次为 **+1.0593、+0.3928、+0.8535、+1.0283、+0.8426 pp**。五个点的收益序列不单调。稿件另外报告两种规模、两种子的双语短预算诊断，但三种子目标实验、配对双语任务及匹配曝光分解仍有明确占位符。因此，当前可评价的是探索性实验及其审计价值，不能评价尚未给出的确认性结果。

## Weaknesses / 主要问题

### W1：核心证据尚未完成，贡献与方法时态仍混合了结果和计划（决定性）

**依据。** P:46–48 明确三种子目标研究仍是确认门槛；P:419–426、450–459、473–481 的分解、主结果、配对评价均为 `ResultTBD` 或 `ClaimTBD`。但 P:88–89 写为已经开展受控配比/顺序实验、已经提供配对评价及污染敏感性重分析；P:294、296 又使用报告所有注册运行、扫描全部训练文档、重复主要分析的完成式表述。P:229–251 的 41-run launch matrix 混列已完成质量实验和冻结双语计划，不能读作已完成 41 次训练；另外 P:565 报告的 24 次短预算诊断是不同矩阵。

**为什么重要。** 读者会把研究方案的完整性误当成实验结果的完整性。公开写了 TBD 比填入虚构数据好，但贡献表述仍必须与实际完成状态一致。这里指出的是证据与表述不一致，不指控作者伪造测量。

**无需大重训的修复。** 增加按实际阶段列出的状态表：已完成质量扫描、已报告短预算双语诊断、尚未完成的 P1/P2 计划分别列出真实模型数、tokens、种子数、可用评测。没有结果的分解、三种子主实验、配对行为与污染重分析移至 Future Work，删除相应的当前贡献和结果占位表。用已有短预算诊断支撑有限范围的语言顺序发现。已知作者没有预算补 143M/803M 种子，本评审不要求将新增种子作为回复阶段必须完成的事项，也不给承诺开展的实验计分。

**小白解释。** “已经设计了考试”和“已经考完且有成绩”是两件事；现在摘要和贡献中仍有句子把它们混在一起。

### W2：`acc_norm` 被误写为 chance-normalized，且任务方向会随评分方式改变（决定性且可直接修复）

**依据。** P:199、288、595 称十任务敏感性指标为 `chance-normalized`。然而 C:183–186 只读取源 `acc_norm`，C:237–239 直接做算术平均；脚本没有随机猜测基线、选项数或 `(accuracy - chance)/(1 - chance)` 的变换。

源数值本身也能否定该解释：56M full 的 HellaSwag `acc=0.2868950408`、`acc_norm=0.3065126469`。四选一随机猜测校正应约为 `0.0491934`，不会是 `0.3065`。MMLU 的 `acc` 与 `acc_norm` 相等，也不符合对四选一准确率进行随机基线扣除的解释。

[LightEval v0.9.2 官方实现](https://github.com/huggingface/lighteval/blob/v0.9.2/src/lighteval/metrics/metrics.py) 将 `loglikelihood_acc_norm` 定义为对答案 log-likelihood 进行 `LogProbCharNorm()` 后选出答案，再平均正确性；另有忽略首个空格的变体。这说明标准含义是**按答案长度归一化评分后的准确率**，不是按随机猜测基线校正准确率。当前 EXPS 未给出具体 harness 版本和任务配置，故我不能据此反向认证这些历史运行究竟采用字符、token 或哪种空格处理；精确定义必须由当时配置确认。

**影响不止术语。** T 的最终记录显示：

| 任务和规模 | 原始 `acc` 的 HQ−full | 源 `acc_norm` 的 HQ−full |
|---|---:|---:|
| HellaSwag，56M | −0.0697 pp | +0.8763 pp |
| OpenBookQA，143M | −2.0000 pp | +0.2000 pp |
| SciQ，143M | +0.8000 pp | −0.1000 pp |
| WinoGrande，56M | +0.2368 pp | −1.6575 pp |

因此 P:343–344 的 HellaSwag 五种规模都下降，只在报告的原始评分口径下成立。十任务宏平均方向在两种现有字段下均为正，不能推出每个任务结论也稳健。

**无需重训的修复。** 把此字段暂时准确命名为“source `acc_norm`”，补充历史 harness commit、每任务 metric、prompt、split、选项处理和长度单位后再写“长度归一化”。同时给出所有十任务的两种评分差值及符号是否一致。若要保留真正 chance-normalized 指标，必须明确每任务随机基线并单独实现、另取字段名；可变选项数要依据实际题目分布处理。外部排行榜的 chance-normalized index 是另一个指标，不能移植其名称来解释质量实验。

**小白解释。** 一个操作是“先把长答案和短答案的分数调到可比较，再选答案”；另一个是“成绩扣掉乱猜能拿的分”。两者不是同一种归一化。

### W3：历史质量干预缺少可审计的数据与训练控制，不能把任务差异直接解释成质量—覆盖机制（主要）

**依据。** E:154 定义 Q0 为无筛选，E:210 又定义为 `score≥0.5`；A 的 `warnings` 明确缺 ordered manifest、unique-document count、train-loss log，并指出 E:226 的“删掉 67% 数据”不可核实。P:175–183 承认阈值模糊，但紧接着 P:185–187 以完成式描述 NFKC、MinHash、污染清理和多源配额流程，容易让人以为它们也已用于历史质量扫描。P:262–263 声称准确更新 manifests 随分析包保留，在本次限定证据中能核对的是 README 超参和 JSON 的 `iter/tokens_B`，未看到能独立证明样本顺序、初始化配对与完整训练控制的运行清单。

**为什么重要。** 两种数据条件可能同时改变域、文体、长度、去重、重复曝光与基准重叠。即使最终 token 数一样，也不能把观察差异唯一归因为抽象的“质量”，更不能从结果反推“覆盖减少”。同一个 benchmark 上两模型可以进行逐题配对；但这不等于训练随机性也完成了配对控制。

**无需大重训的修复。** 将已证实的 run 控制、README 描述但未验证的控制、重建设计未来要用的控制分开。能找回则补阈值配置、语料 revision、score 模型、去重顺序、训练初始化/种子、样本或分片清单、唯一 tokens/重复次数和 checkpoint 哈希；找不回就明确未知，并仅称仓库条件 `ultra-en` / `ultra-en-hq` 的历史比较。可对现存训练语料或固定样本做域、长度、重复与污染审计，但抽样审计须写覆盖范围，不冒充全语料验证。把 P:343 的“repeatable quality–coverage trade-off”改为“observed task-dependent differences”；覆盖机制留作假说。

**小白解释。** 如果筛选后不仅文字变好，还换了题材、减少了重复或增加了考试原题，模型分数变化就不能只归功于“质量更高”。

### W4：单种子与 checkpoint 重复测量限制了不确定性；当前文字局部仍越过限制（主要）

**依据。** A 的 `checkpoint_counts`、`paired_checkpoint_count=101`、`complete_macro10_checkpoint_pairs=100` 与 `warnings`；P:230、294、601–610 正确说明每条件一条轨迹、没有逐题记录。P:343 却称模式“repeatable”；P:63 提问“repeatable benefit”，如后文被读作肯定回答也会产生误导。`98/100` 只是共享初始化、数据和优化历史的多个时点。五种规模也不是同一规模上的五次随机重复。

**判断。** 不能据此给种子层面的 CI、把 98/100 作为成功概率或显著性检验。五点回归的 `R²=0.0015198`（`tables/key_numbers.json: final_gap_log_size_regression`）描述这五个点线性拟合很差，不是“模型大小不影响筛选收益”的无效应证明。P:305–309 大体谨慎，应保留“在观测点未见单调趋势”的限定。

**无需重训的修复。** 全文统一为 descriptive / single-run，展示精确任务差值与完整轨迹。若十个最终 checkpoint 仍可访问，只重新评测并存同题两条件的预测、log-likelihood 和 ID，然后做 paired item bootstrap；明确所得区间只覆盖给定训练模型的测试题不确定性，不能估计重训波动。若模型或逐题结果不可得，就继续只报点估计。新增 143M/803M 种子只写未来研究；禁止用 checkpoint、任务数或 bootstrap 重采样次数替代训练种子数。

**小白解释。** 同一个学生每个月考一次，不能当作 20 个不同学生参加实验。多记录几次能看学习过程，却不能知道换一个学生还会怎样。

### W5：宏平均定义合理，但它的选择与任务分类需要敏感性说明，不能把 ARC 驱动的收益推广到知识/常识机制（主要）

**完整口径。** C:30–41 列出 MMLU、ARC-E、ARC-C、SciQ、OpenBookQA、HellaSwag、PIQA、SIQA、WinoGrande、CSQA；C:228–239 对十个任务等权，每任务 10%，不按 `n` 加权。263M/6.291B 缺 SciQ 时整个宏平均位置排除，而非改成九任务平均。这个主口径计算正确，但“透明”不等于不存在价值选择：ARC-E/C 占 20%，MMLU 整体只占 10%；各任务内部汇总方式仍需 harness 配置确认。

**依据与复算。** 根据原始最终 JSON 的 `results.{task}.{acc,n}`，并与 T/M 交叉核对：

| 规模 | 十任务等权原始宏平均差 | 去掉 ARC-E/C 后八任务均值差 | 按存储 `n` 加权的差 |
|---|---:|---:|---:|
| 56M | +1.0593 pp | +0.8093 pp | +0.4942 pp |
| 143M | +0.3928 pp | −0.3777 pp | −0.3445 pp |
| 263M | +0.8535 pp | +0.3957 pp | +0.3869 pp |
| 469M | +1.0283 pp | +0.0218 pp | +0.4970 pp |
| 803M | +0.8426 pp | +0.0718 pp | +0.0932 pp |

计算公式分别为 `mean_t(100*(hq_acc-base_acc))`、对非 ARC 八任务取同式均值、以及 `sum_t(n_t*gap_t)/sum_t(n_t)`；最终总 `n=35412`。最后一列仅是按存储任务人数的加权敏感性，不在缺失原评测汇总定义时声称已重建逐题微平均。去 ARC 分析同样是事后诊断，不能替换主成绩或作为新的检验。它说明 143M 的全任务正结论依赖等任务权重，较大两档的正宏平均也很受 ARC 驱动。

C:55–58 把 MMLU/ARC/SciQ/OpenBookQA 归作 knowledge_science，其余五项归作 commonsense_social；E:199 却把 OpenBookQA 标成常识。F 的两个分组收益均不单调。R 第 3.1 节已经正确指出这种事后分类与选择性解释风险，P:343 的机制式措辞仍应收敛。

**无需重训的修复。** 保留预先声明的十任务主宏平均并交代它是回溯重分析口径；附 leave-one-task-out、相关任务组剔除和 `n` 加权敏感性，完整显示正负结果，不筛选有利权重。以具体任务名称报告发现，不把 ARC 与 HellaSwag/PIQA 的对照包装成所有知识任务与所有常识任务的规律。仅凭该主宏平均为正不能推出可执行的普遍数据配方。

**小白解释。** 每门课权重相同，和每道题权重相同，会得到不同总分。两种总分都能有用途，但必须告诉读者用的是哪一种，以及收益是否由少数科目带动。

### W6：固定 token 研究不是等算力研究，比例扩展和曝光分解还需限定因果含义（次要至主要）

**依据。** P:178、191–195、245 固定约 20B tokens；E:39–45 显示同时改变宽度、层数与非 embedding 参数，E:169–183 给共同训练超参。同规模 full/HQ 在存储的最终步数与 token 数上匹配，这支持条件内比较；但跨规模 FLOPs 不相同，约 20B tokens 对 56M/803M 分别约为 357/25 tokens per parameter。因此它估计的是固定数据量下这组架构的条件差异，不能回答同样算力该选多少参数或哪种筛选策略。P:387–390 对双语比例扩展已承认参数、tokens、updates 与 pool 一起变，应保留此限定。

P:203–210 的分解是恒等式，但单语 `qC` 中间 checkpoint 与双语 `C` 最终 checkpoint 的优化时钟不同：P:256 使用随总更新退火的 cosine LR，中间单语点没有走完整段退火。残差因此包含这套训练程序下额外更新与 LR 时机的综合影响，不能等同纯粹的跨语言表示共享机制；log-exposure 插值也不是直接测量。P:210 已说不是表示定理，仍建议使“transfer/interference”在全文保持操作性定义。

**无需大重训的修复。** 给出 tokens、最终更新、架构与估算/实测 compute 的对应表，明确没有等 FLOPs 结论；若无实测则不要捏造 GPU-hours。未来曝光分解报告匹配点的实际学习率、更新数和插值范围，并将残差叫作“给定训练协议下的匹配曝光差”。现有 checkpoint 可用于插值敏感性或学习曲线核对，但没有匹配终止 LR 的额外实验时，不宣称已分离表示共享机制。分解本身既然尚无实测表，应随 W1 一并移入未来研究。

**小白解释。** 大模型读同样多的书仍更费计算；而一个模型刚学到一半、另一个已经完成退火收尾，即便它们读过同样多中文，差别也不只来自有没有读英文。
