# 论文主线重构：为什么 Scale 实验必须进入正文

> 历史故事方案，保留供追溯。两组 Scale 进入正文的决定继续有效，但语言比例扫描未完成、完整配方仍是目标；143M/803M 补种子延期。固定 IID 的质量四格不能测质量×顺序交互。当前状态与贡献请读 [进展总览](../current/PROGRESS_CN.md)。

## 先说人话版结论

这组 Scale 实验不应该只放附录。

原因不是“我们花了很多卡，所以必须多占篇幅”。论文不按算力报销版面。真正的原因是：这组实验正面回答了一个重要、清楚、可复查的问题——**在训练 token 都约为 20B 时，把英文网页数据筛得更严格，对 56M 到 803M 的小模型到底有没有用？**

答案也不是一句空泛的“高质量数据更好”，而是三层更有价值的结论：

1. 在五个模型规模的最终 checkpoint 上，过滤版的十任务平均分都更高，增益为 **+0.39 到 +1.06 个百分点**。
2. 增益并没有随着模型变大而单调增加，五点拟合的 $R^2=0.002$。所以不能说“模型越大，过滤越重要”，也不能把它叫作 scaling law。
3. 不同任务反应不同：ARC-Easy 和 ARC-Challenge 五档都提高，HellaSwag 五档都下降，PIQA 四档下降。这说明过滤提高了某些知识/推理能力，同时可能损失了某些覆盖面或文本风格。

换句话说，我们得到的不是一句广告词，而是一条有条件的训练经验：**小模型确实会从数据筛选获益，但过滤不是免费的，也不是对所有任务都好；必须同时检查平均分与逐任务退化。**

## 新的论文中心故事

论文可以从“只研究中英双语顺序”调整为：

> 我们给出一套面向超小型中英双语基础模型的、可审计的训练配方，并用受控实验研究配方中的三类数据决策：选什么数据、两种语言各分多少 token、这些 token 按什么顺序出现。

这条主线可以画成下面的逻辑链：

```text
原始语料
   ↓  第一步：质量筛选——哪些文档留下？
可训练语料池
   ↓  第二步：语言配额——英文和中文各占多少？
固定 token 预算
   ↓  第三步：课程顺序——随机混合还是分块训练？
143M 中英双语模型
   ↓
分别报告英文、中文、配对行为与遗忘，而不是只报一个平均数
```

两组现有大实验在这条链上各司其职：

- 56M–803M、固定 20B token 的英文实验回答“第一步怎么筛”。
- 43M→143M 的中英实验回答“第二、三步怎么配、怎么排”。

二者不是同一个因果实验。英文过滤实验不能直接证明中文也受益；双语顺序实验也没有比较过滤阈值。论文必须明确说它们是**训练配方中的两个互补证据轴**，而不是假装已经完成一个统一的全因子实验。

## Scale 实验在正文中放什么

正文应该保留：

- 一张五档模型的最终结果表；
- 一张四面板主图，展示最终平均分、过滤收益随规模的变化、逐任务差异和训练轨迹；
- 三个核心数字：五档均为正、增益 +0.39～+1.06 pp、规模交互 $R^2=0.002$；
- ARC-E/ARC-C 始终提高而 HellaSwag 始终下降的任务异质性；
- 一段明确的证据边界：每个格子只有一次训练，不能做种子显著性结论。

附录保留：

- 原始 JSON 的 `average` 实际只平均四个任务的字段审计；
- 10 任务透明均值与原始 4 任务均值的差别；
- 101 个 checkpoint 对中有一个 SciQ 缺失；
- “full”到底是完全未过滤还是 score≥0.5 的 README 描述冲突；
- 为什么 98/100 个 checkpoint 为正不能当成 100 次独立重复实验；
- 所有逐 checkpoint 数字和复现文件。

这样既能体现实验价值，又不会把正文塞成审计日志。

## 目前可以说什么，不能说什么

### 可以说

- 在固定约 20B token 的五档英文训练中，高分过滤条件在最终十任务平均分上均优于 full 条件。
- 平均收益较小但跨规模方向一致。
- 收益具有明显任务差异，符合“质量与覆盖面之间存在权衡”的解释。
- 在已经完成的两种规模的双语实验中，持续 IID 混合比长语言块更稳健；一次大切换明显偏向最后训练的语言。
- 这些结果共同支持一套“逐任务审核数据质量、持续混合两种语言、分别报告两种语言”的条件式配方。

### 不能说

- 不能说发现了新的 scaling law。
- 不能说过滤收益随模型规模增加而增加。
- 不能说 score≥0.9 对所有任务都更好。
- 不能说英文过滤实验证明了中文也会获益。
- 不能说 98/100 个 checkpoint 相当于 100 个独立重复实验。
- 不能说过滤机制一定是“内部过滤器”或某种理论机制，因为没有相应干预。
- 不能声称公开的 Haidass1.5 400B-token 原始配方已经被精确复刻；模型卡缺少比例、阶段和 shard 等信息。

## 红军会怎么攻击，蓝军怎么回答

### 攻击 1：这只是“好数据更好”的常识

回答：如果只报一个规模、一个平均分，确实很弱。这里的价值在于固定训练 token、覆盖五档模型，并公开了反例任务。结果否定了两个过强直觉：“模型越大越依赖质量”和“严格过滤对所有任务都有利”。贡献是受控证据和边界，不是发明“质量”这个概念。

### 攻击 2：英文 Scale 和中英双语是两篇论文硬拼

回答：两者都属于同一条小模型数据配方链，但证据边界必须分开。为了让连接更强，下一轮应该补一个桥接实验，直接测试中英语料质量与双语混合的交互。

### 攻击 3：每格只有一个 run，结论不稳

回答：正文把它标成大规模探索性扫描，只做描述性结论，不报伪造的置信区间。再在关键规模补种子与 item-level 评测，把最关键结论升级为确认性证据。

### 攻击 4：20B token 对 56M 与 803M 的优化程度不同

回答：这是固定 token 预算下的数据干预，不是 compute-optimal scaling。实验回答的是“同样看到 20B token 时，过滤效果在不同容量下怎样”，不能回答各尺寸的最优训练量。

## 最务实的补实验优先级

### P0：不重训即可完成

1. 对 10 个最终模型保存逐样本预测，做 paired bootstrap 置信区间。
2. 补齐 full 条件的精确定义、数据 revision、过滤阈值、文档数、去重后 token 数和有序 manifest。
3. 报告每个任务的样本数、chance level、评测 harness 版本和 exact command。

这些工作不会解决训练随机性，但能解决评测不确定性与复现问题。

### P1：最少量确认性重训

- 在 143M 和 803M 上，full/filtered 各补 2 个种子，使每个条件达到 3 seeds。
- 固定初始化配对、数据 token 数、训练步数和评测版本。
- 预注册主指标为十任务 raw macro，逐任务结果必须完整报告。

这能直接检验目前的正增益是否只是某一次训练的随机波动。

### P2：连接“数据质量”与“中英双语”的桥接实验

建议在 IID 50:50 下做一个 2×2 质量设计：

| 条件 | 英文数据 | 中文数据 | 回答的问题 |
|---|---|---|---|
| Q0 | full | full | 基线 |
| Q-EN | filtered | full | 只提高英文质量会怎样影响两种语言 |
| Q-ZH | full | filtered | 只提高中文质量会怎样影响两种语言 |
| Q-BOTH | filtered | filtered | 两边都筛是否最好 |

先在 43M 做至少 2 seeds 筛查，再在 143M 对关键比较做 3 seeds。每个 run 的总 token、英文/中文比例、初始化、更新数和 tokenizer 必须完全一致。主要看：

- 英文和中文各自的 held-out BPB；
- 语言平均相对 BPB；
- Belebele/XCOPA 的中英配对正确率；
- 过滤是否改善本语言却伤害另一语言；
- 过滤和语言顺序是否存在交互。

如果中文没有可直接使用的同类 fastText 分数，就必须先冻结一个对称的中文质量规则或人工标注校准集，不能临时根据结果改阈值。

## 建议的正文顺序

1. 引言：小模型的数据配方有三个决策——筛选、配额、顺序。
2. 相关工作：小模型、数据质量与覆盖面、多语言干扰、数据混合。
3. 模型与数据：Haidass1.5、质量过滤条件、中英重构语料。
4. 实验设计：五档固定-token 扫描；中英比例与顺序控制。
5. 主结果一：数据质量在五档规模上的收益与任务异质性。
6. 主结果二：43M→143M 的双语混合与顺序效应。
7. 143M 三种子确认实验与配对中英评测。
8. 局限：单次质量扫描、英文到中文不可直接外推、原始 400B 配方不可精确复刻。

## 给作者团队的一句话版本

> 我们不是在说“过滤永远更好”或“IID 永远最好”；我们用大规模受控实验说明，超小型双语模型的效果取决于一条可审计的数据决策链：严格过滤能带来小而稳定的平均收益但会牺牲部分任务覆盖，持续双语混合则比长语言分块更能保住两种语言，因此可靠配方必须逐任务、逐语言报告，而不能只看一个总分。
