# EXPS 五档数据质量 Scale 实验：严格复算报告

## 摘要

本报告独立复算 `DALabCommunity/EXPS` 提交 `4d45f05583e7370fd452a99635d4c984a9eb9d5e` 中的五档英文预训练实验。实验在 56M、143M、263M、469M、803M 参数规模上，分别使用 Ultra-FineWeb-en 全量数据和 `fastText score >= 0.9` 子集训练至约 20B tokens，并沿训练轨迹做 zero-shot 下游评测。

最稳妥的描述性结论是：**在最终 20B-token checkpoint，过滤数据在五个规模上的透明十任务宏平均均高于全量数据，原始准确率增益为 +0.39 至 +1.06 个百分点；但该增益与参数量没有可识别的单调关系。**任务间异质性明显：ARC-E 和 ARC-C 在五档规模均为正，HellaSwag 在五档规模均为负，PIQA 仅在 56M 为正。

这是一项有价值的探索性规模扫描，但目前每个“规模 × 数据条件”只有一条训练轨迹，没有随机种子重复、逐题预测、训练损失和可审计的数据清单。因此不能宣称统计显著、普适规律、精确拐点或机制因果。

README 对 baseline 的文字定义存在内部矛盾：实验设计部分写“无筛选全量”，结论部分写“score≥0.5（全量）”。在同事补交数据 manifest 前，本报告只使用仓库条件名 `ultra-en` / `ultra-en-hq`，并将后者按文档记为 score≥0.9；论文不应断言 baseline 的精确阈值。

### 1.1 原始 `average` 字段的口径问题

逐点重构证明，JSON 中的 `average.acc` 精确等于以下四项原始准确率的等权平均：

1. HellaSwag；
2. ARC-Easy；
3. ARC-Challenge；
4. PIQA。

最大重构误差为 `1.11e-16`。它不是十任务平均。原 README 将这个字段用于 “Overall” 叙述，会放大特定四任务对总结果的支配。本文重新报告：

- 十任务原始准确率宏平均，作为主分析；
- 十任务 `acc_norm` 宏平均，作为口径敏感性分析；
- 原四任务平均仅用于审计对照，不作为新的总成绩。

## 2. 最终 20B-token 结果

| 参数量 | 全量数据十任务平均 | HQ 十任务平均 | HQ − 全量 | HQ 胜出任务数 |
|---:|---:|---:|---:|---:|
| 56M | 39.00% | 40.05% | +1.06 pp | 9/10 |
| 143M | 42.34% | 42.74% | +0.39 pp | 4/10 |
| 263M | 43.96% | 44.81% | +0.85 pp | 6/10 |
| 469M | 45.51% | 46.54% | +1.03 pp | 6/10 |
| 803M | 46.60% | 47.44% | +0.84 pp | 5/10 |

五个最终点方向均为正，但序列 `1.06 → 0.39 → 0.85 → 1.03 → 0.84 pp` 明显不是单调曲线。用 `ln(参数量)` 对最终十任务增益做五点线性拟合，斜率为 `+0.010 pp / ln(N)`，`R² = 0.0015`。这相当于说参数量几乎不能解释这五个最终增益的差异。

使用十任务 `acc_norm` 宏平均时，五档增益仍均为正，约为 `+0.77、+0.75、+0.90、+1.23、+1.01 pp`。正方向对指标口径不敏感，但“随规模单调变化”的结论仍不成立。

### 3.1 可复述的任务结论

- ARC-E/ARC-C 是最稳定的正向证据：五档规模均为正。
- HellaSwag 是最稳定的负向证据：五档规模均为负，但 56M 只有 -0.07 pp，接近零。
- PIQA 在 56M 为正，其余四档为负；其“随规模变差”的五点拟合 `R²≈0.82`，值得复现实验重点检验。
- “所有知识任务都会随规模获得更大 HQ 收益”不成立：SciQ 的最终收益反而总体下降；MMLU 和 OpenBookQA 方向不稳定。
- 将任务事后分成五个“知识/科学”和五个“常识/社会”任务后，两个分组的增益都不随规模单调变化。只选 ARC 对比 HellaSwag/PIQA 会得到更整齐的故事，但属于事后选择，不能包装成预注册结论。

## 4. 训练阶段分析

在 100 个完整十任务 checkpoint 对中，HQ 十任务宏平均有 98 个为正。两个非正点分别出现在 263M 的约 1.05B tokens 和 803M 的约 13.63B tokens。

但是，这 100 个点不是 100 次独立实验；它们来自十条训练轨迹上的重复测量。不能把 checkpoint 当随机种子计算显著性，也不能据此写“98% 概率有效”。

对每个共同 checkpoint 拟合“HQ 增益对 log 参数量”的斜率：

- 10B tokens 之前的平均斜率约 `-0.043 pp / ln(N)`；
- 15B tokens 之后的平均斜率约 `+0.005 pp / ln(N)`；
- 各 checkpoint 的斜率正负反复变化。

因此当前透明十任务口径不支持 README 中“早期大模型获益更多、后期大模型获益更少、10–15B 发生反转”的强结论。

## 5. 机制解释的证据边界

“过滤提高内容质量但降低多样性”是与结果相容的合理假说：ARC 可能更受益于事实密度和清晰文本，而 HellaSwag/PIQA 可能依赖更广的日常场景。但现有产物没有提供：

- 过滤前后文档数、唯一 token 数和重复轮数；
- baseline 究竟是无筛选还是 score≥0.5 的明确配置；
- 相同文档/相同 token 的配对数据清单；
- 宽域与高质量域上的验证 loss；
- 逐题预测和错误类型；
- 多随机种子训练。

因此“多样性不足”和“大模型具有内部过滤器”只能写成待验证假说，不能写成已经证明的机制。

## 6. 对 Haidass 论文的定位

该实验是英文单语数据质量研究，而 Haidass 论文核心是 143M 预算下的中英双语分配与顺序效应。两者并非同一个因果问题。最稳妥的处理是：

- 放在附录，作为数据策划的探索性补充；
- 不列为 Haidass 的核心贡献；
- 不用它解释中英干扰或遗忘；
- 后续在中英两种语言各自设置质量阈值后，才能与双语核心问题建立直接联系。

## 7. 最务实的补实验顺序

1. **无需重训，先补逐题输出。** 对最终十个模型重新评测并保存每题正确性、log-likelihood 和样本 ID，做同题 paired bootstrap。
2. **补数据审计。** 给出全量/HQ 的文档数、唯一 token、重复 epoch、语言和域分布、阈值前后去重策略及哈希。
3. **先复现两个关键规模。** 143M 和 803M 各补至少两个随机种子，直接检验“质量 × 规模”交互；预算允许再补 56M。
4. **补阈值曲线。** 至少加入 0.7、0.8、0.9 三档，区分“质量提高”与“删得过狠”。
5. **补两套验证 loss。** 同时在宽域网页集和 HQ 同域集上评测，判断收益来自真正泛化还是分布对齐。
6. **再做双语版本。** 分别过滤英文、中文或两者，固定中英 token 配比，检查数据质量是否改变跨语言干扰。

## 8. 论文可用结论

建议英文表述：

> In an exploratory single-run sweep with a fixed 20B-token budget, score-based filtering improved the final ten-task macro average at all five model sizes (56M–803M), by 0.39–1.06 percentage points in raw accuracy. The gain was non-monotonic in model size (log-linear R²=0.002) and heterogeneous across tasks: ARC-Easy and ARC-Challenge improved at every size, whereas HellaSwag declined at every size. These results motivate, but do not establish, a quality–diversity trade-off; seed replication and item-level paired uncertainty remain required.

不建议使用“scaling law”“精确拐点”“普适提升”“内部过滤器已证实”等措辞。
