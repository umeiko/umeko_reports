# EXPS 数据质量 Scale：红军、蓝军与虚拟 AC 意见

## 蓝军：怎样陈述这项工作的价值

1. 五个参数规模覆盖 56M–803M，比常见的两个规模点更能暴露非单调性。
2. 每个模型固定约 20B 训练 tokens，避免把“多训练了”误认为“数据更好”。
3. 训练轨迹上进行了密集的下游评测，不只挑选最终 checkpoint。
4. 十个任务显示出清晰异质性：总体小幅为正，但 ARC 与 HellaSwag/PIQA 方向不同。
5. 该结果对实践有意义：数据筛选策略不应只由一个综合平均分决定。

建议主张：这是一个“fixed-token data-quality scale sweep”，揭示任务级质量—多样性权衡的探索性证据。

## 红军：审稿人最可能攻击什么

1. **没有随机种子。** 五个 scale 点不是五次重复，不能给出统计显著性。
2. **原 average 名不副实。** 它只含四个任务，却被当作总体平均，可能构成选择性报告。
3. **任务分类是事后选择。** 只把 ARC 叫知识、Hella/PIQA 叫常识，会得到漂亮故事；但 MMLU、SciQ、OpenBookQA、SIQA、CSQA 并不都服从该故事。
4. **缺少逐题预测。** 无法做同一测试题上的配对置信区间。
5. **缺少数据暴露量审计。** HQ 子集更小，如果为了读满 20B tokens 而重复更多轮，实验同时改变了质量、覆盖面和重复率。
6. **baseline 定义矛盾。** README 一处写无筛选，一处写 score≥0.5；没有配置或 manifest 可裁决。
7. **机制没有直接证据。** “内部过滤器”和“多样性不足”都只是解释，不是测量结果。
8. **训练阶段反转不稳。** 透明十任务口径下，早期与后期的 size slope 没有呈现 README 所称的稳定反转。
9. **与双语论文存在范围漂移。** 全英文数据过滤不能直接解释中英双语共享容量和遗忘。

## 蓝军回应与必要修改

- 将所有结果明确标记为 exploratory single-run sweep。
- 主平均改成十任务等权宏平均，并把四任务旧口径只放审计说明。
- 报告原始准确率和 normalized accuracy 两种口径；二者都为正时再说方向稳健。
- 删除精确 50M、111M、298M 拐点，除非补随机种子、预注册拟合形式并报告区间。
- 将“内部过滤器”改为 future hypothesis。
- 在正文最多用一段，完整结果放附录；双语实验仍是主线。

## 虚拟 AC 决策

**当前建议：作为 Haidass 附录的探索性结果保留，不作为核心接收理由。**

原因：实验矩阵大、现象有价值，但统计独立性和数据审计不足，且原平均口径存在明显歧义。若补齐 143M/803M 多种子、逐题 paired bootstrap、数据重复率/多样性审计，并做一个中英双语质量过滤桥接实验，这一支线可以升级为有竞争力的次级贡献；否则应克制地放入附录。
