# 榜单与对比模型方案

## 1. “打榜”分成三类

### 官方共享任务

WMT 是最重要的正式入口。WMT26 已经结束提交，当前只能在公开测试集上做 `post-hoc/offline` 结果，不能称为官方排名。WMT27 的方向、规则、日期和提交格式尚未公布，公告后再新建版本化参赛清单。

### 固定公开基准

FLORES+、WMT24++、NTREX-128 和 TICO-19 可以形成长期可复现的模型卡分数。这类不是持续更新的在线排行榜，但适合论文表格和 Hugging Face 模型卡。

### 与公开系统输出比较

不需要把所有同期模型重新部署一遍。[WMT26 官方仓库](https://github.com/wmt-conference/wmt26-general-mt)已经公开测试数据、系统提交和人评；[MT Metrics Eval](https://github.com/google-research/mt-metrics-eval)提供 WMT 2019 起的源文、参考、部分系统输出、自动指标和人评信息，也包含 WMT24++ 的部分系统输出。使用这些公开输出，可以在完全相同的参考、SacreBLEU/COMET 版本下重算分数，成本低且比抄论文中不同口径的数字可靠。

## 2. 哪些基线自己跑

| 层级 | 模型 | 为什么需要 | 如何比较 |
|---|---|---|---|
| 必须 | 原始 Haidass1.5-143M | 唯一能回答 SFT 带来多少增益 | 同一 prompt、同一解码、全测试集 |
| 必须 | A1 翻译 SFT 主模型 | 论文和模型卡主结果 | 3 seeds 的 1M 设置；8M 主设置 |
| 建议 | Helsinki-NLP OPUS-MT en→zh / zh→en | 经典的专用双向模型，部署成本低 | 分方向跑；固定精确 revision |
| 建议 | NLLB-200 distilled 600M | 强的公开多语言 MT 锚点 | 明确它约 600M、比 143M 大约 4.2 倍；许可 CC-BY-NC-4.0 |
| 可选 | 一个公开的 0.5B 左右通用双语 LLM | 判断专门翻译 SFT 是否优于更大通用模型 | 固定公开 checkpoint，不做针对测试集的 prompt 搜索 |

OPUS-MT 两个方向是两个模型，而 Haidass 是一个双向模型，比较时同时报告“单模型总参数/权重体积”和“每方向质量”。NLLB-200 distilled 600M 的模型卡将其定位为句级、多语言研究翻译模型，输入训练长度不超过 512 tokens；不要用它的文档弱点来夸大 Haidass 的优势。

## 3. 哪些结果直接用公开产物

- WMT26：下载官方提交 JSONL，筛选英文→简体中文，使用同一个公开参考和本项目固定指标重算；若报告官方人评，保留原始系统名、评价版本和置信区间。
- WMT19–23：优先通过 MT Metrics Eval 加载同一 EvalSet 的公开系统输出，不从论文 PDF 手抄分数。
- WMT24++：使用 MT Metrics Eval 公开的 `sys_names` 对比；官方说明部分系统因限制未公开，因此表格必须写“公开子集”，不能暗示覆盖全部参赛者。
- 没有逐句输出、只有论文总分的系统：可放“文献报告值”附表，但必须记录指标版本、参考、tokenizer 和是否可直接比较；口径不明时不进入主排名。

## 4. 公平比较规则

主表至少分三组：

1. 相近规模、开放权重、自己重跑。
2. 更大开放翻译模型，作为质量上限锚点。
3. WMT 官方公开系统输出/人评分，作为同期生态参考。

不能把 143M 模型和闭源超大模型放在一列只按分数排完，然后声称“第二名”。还要报告参数量、是否一个模型支持双向、是否使用文档/图像上下文、训练数据是否公开、是否离线重算和许可证。

所有可比自动分数使用同一套：SacreBLEU 签名、chrF++、固定 revision 的 COMET。官方人评分与我们自己的自动分数分栏，不混成一个排名。

## 6. WMT27 公告后的待办

1. 冻结公告页面和规则版本，确认中英方向。
2. 决定 constrained/unconstrained 或届时等价 track，核对权重开放和训练数据要求。
3. 在官方 blind test 发布前冻结唯一 primary system。
4. 按官方 schema 写输出验证器，保留 `doc_id`、目标语言和 hypothesis。
5. 预留系统论文、模型卡、权重和数据说明时间；不要等翻译截止后才补许可证。
